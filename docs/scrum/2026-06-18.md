## 1. 전날(6/17) 회의 핵심 피드백 정리

### 🔥 핵심 지적 — 개발 방식 문제

> "로컬 테스트 끝나고 나서 인프라 올려야지, 처음부터 서버/터널링 깔고 작업하니까 다 터지는 거다"

| 우리가 한 방식 (잘못된) | 올바른 방식 |
|------------------------|------------|
| 인프라(터널링·서버) 먼저 구성 → 그 위에서 작업 | 로컬에서 품질 먼저 → 인프라는 나중 |
| 시행착오 중에 기준을 버림 | 기준 유지하면서 시행착오 |
| 터널링 붙이고 테스트 | 로컬 데모 완성 → 환경 체크 → 런칭 |

**결론:** 스택 선정은 경험이 있어야 처음부터 잘 됨. 경험이 없으면 기준을 지키면서 시행착오해야 함.

---

### 🎬 영상 파트 (장민수 / LivePortrait) — 진행 경과

**시도한 방향 및 막힌 지점:**

| 방향 | 문제 |
|------|------|
| MuseTalk → LP | LP animals가 사람 얼굴에서 동물 표정 값을 못 뽑음 → 말티즈가 가만히 있음. 연결하려면 별도 어댑터 학습 필요 |
| LP → MuseTalk | MuseTalk 내부 얼굴 검출 모델이 사람 전용 → 강아지 얼굴 입력 시 얼굴 없음 처리 |
| 동물 전용 립싱크 오픈소스 | 데이터셋·모델 찾기 매우 어려움. 하나 발견했으나 비공개 코드라 사용 불가 |

**현재 채택 방향:**  
LP keypoint 구조 직접 분석 → 오디오 에너지를 keypoint에 매핑 → 입 개폐·눈 깜빡임·고개 움직임 직접 구현

**성능 (현재):**
- 해상도: 256×256 (512×512 시 GPU 뻗음, 128×128 시 이미지 깨짐)
- 모델 로딩: ~5초
- 프레임 렌더링: 1869프레임 ÷ 7fps = **약 4분 30초**
- 오디오 합치기: ~5초
- **총 약 4~5분 소요**

**피드백 방향:**
- 터널링은 나중 문제 — 로컬에서 품질 좋은 결과물 먼저
- 이미지 → 음성 분리 → 톤 변환 → 전송/재생 순서로 가능성 확인
