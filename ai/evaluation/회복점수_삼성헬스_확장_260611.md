# 회복점수 × 삼성헬스 — 설계·흐름 노트

> 작성 정환주 · `ai/evaluation/` · 최종 갱신 2026-06-12
> **목적:** 삼성헬스의 **객관 수면·활동 데이터**를 회복점수에 반영(+주관 감정과 교차검증).
> 코드 세부는 각 파일(`health_signal.py`·`health_adapter.py`·`health_export_adapter.py`)에 있고,
> 이 문서는 **무슨 데이터를 어떻게 쓰는지 / 전체 흐름 / 남은 일**만 정리합니다.

## 0. 결정 요약 (확정 사항)

| 항목 | 확정 | 이유 |
|------|------|------|
| 회복점수 핵심 가중치 | 감정 40 · 미션 35 · 꾸준 25 | 결정문서 §1 정본 |
| 활동(걸음) | 점수 **+10** (add-on) | 객관 활동은 반영 |
| **수면** | 점수 **제외** | 못 잤다고 회복점수 깎으면 안 됨 → 교차검증·표시로만 (결정문서 §2) |
| 미션 천장 | 35 | base·blend 통일(다르면 점수 튐) |
| 수면 측정(v1) | 객관 수면시간 | 점수엔 안 들어가니 표시·교차검증 한정 |
| 부분 데이터 | 재정규화(옵션 A) | 빠진 신호는 분모서 제외 → 데이터 없다고 점수 안 깎임 |

## 1. 왜

지금 회복점수는 **주관 감정 체크인(1~10)** 위주 → 매번 입력해야 하고 주관적.
삼성헬스에 이미 쌓이는 수면·활동을 더하면 ① 객관성 보강 ② "센서는 수면이 나쁜데 본인은
괜찮다더라" 같은 **숨은 위험** 포착.

---

## 2. 무슨 데이터를 가져와서 어떻게 쓰나 ★

> 핵심. "연결"이 목적이 아니라 **무슨 항목을 어디에 쓰는지**가 설계입니다.

| 데이터 | 어디서 | 회복점수 | 그 외 활용 |
|--------|--------|----------|-----------|
| **걸음 수** | 삼성헬스 `Steps` (하루 합산) | ✅ **활동 +10점** (8000걸음=만점) | 활동 미션과 연동(예정) |
| **수면 시간** | 삼성헬스 `SleepSession` (취침~기상) | ❌ **제외** | ① 교차검증(감정과 대조) ② **컨디션 추정**(`condition_signal`) ③ 리포트 "참고" 표시 |

**왜 걸음만 점수, 수면은 빼나?**
- 걸음 = 회복기 **활동성**의 직접 신호 → 점수 add-on 적합.
- 수면 = 애도기엔 못 자는 게 정상 → 점수로 깎지 않고, **객관 수면 vs 주관 기분의 어긋남**을
  잡는 교차검증·컨디션 추정 재료로만.

> ⚠️ **수면은 "두 트랙"이 따로 있습니다(이름만 같고 데이터·담당·코드가 다름):**
> | 트랙 | 데이터 | 용도 | 담당 |
> |------|--------|------|------|
> | **객관 수면시간** (본 문서) | 삼성헬스 `sleep_hours` | 교차검증 · 컨디션 추정 · 표시 | **정환주** |
> | **주관 수면질 5단계** | `sleep_quality`(1~5 체크인) | **미션 난이도 보조** | 반소람(modifier)·모세종(스키마)·민경이(UI) |
>
> 둘 다 **회복점수 산식에선 제외**(이건 일치). 코드 경로도 완전 별개라 서로 안 닿음.

> 주의: 데이터는 **하루치만** 가져와 넘긴다(여러 날 합치면 과대평가).

## 3. 회복점수 산식

| 항목 | 가중치 | 반영 |
|------|--------|------|
| 감정(주관) | 40 | ✅ 항상 |
| 미션 누적 | 35 | ✅ 항상 (천장 35) |
| 꾸준함(최근14일 체크인) | 25 | ✅ 항상 |
| 활동(걸음) | 10 | ⭕ 들어올 때만 |

각 항을 0~1 비율로 환산 → 가중합 → 들어온 항목의 가중치 합으로 나눠 0~100.
**예:** 감정 8 · 미션 10개 · 꾸준 80% · 9000걸음 → **65점** (활동 데이터 없으면 61점 →
걸음이 들어오면 올려주는 방향, 깎지 않음).

## 4. 교차검증 — 수면(객관) vs 감정(주관)

수면은 점수엔 없지만 여기서 살아있음. **점수 안 깎고 플래그 + 따뜻한 문장**만.

| 수면 | 감정 | 의미 |
|------|------|------|
| 나쁨 | 좋음 | `mismatch_high_risk` — "못 잤다는데 괜찮다고 함" = **숨은 위험** |
| 좋음 | 나쁨 | `mismatch` — 잘 잤지만 마음이 무거움 |
| 나쁨 | 나쁨 | `agree_low` — 몸도 마음도 지침 |
| 그 외 | | `agree_ok` |

보호자에게 보이는 문장은 비낙인·위로 톤, 임상 해석은 내부 코드로만. (1393 위기 트랙과 별개)

**컨디션 추정(`condition_signal`):** 위 교차검증 + 수면·감정을 묶어 **오늘 컨디션(양호/주의/보통)
+ 신뢰도**를 낸다. 강사 구상("수면+체크인 → 컨디션 추정")이 바로 이것. 예: 수면 82+기분 좋음 →
양호/높음, 수면 나쁨+기분 좋음 → 주의/낮음(숨은 위험). **회복점수와 별개 출력**으로 리포트 응답
`recovery_signal.condition` 에 실린다.

## 5. 전체 흐름

```
삼성헬스 앱 ──(설정: Health Connect 동기화 ON)──▶ Health Connect
                                                       │
 [실시간]  RN 앱(개발빌드) ─걸음·수면 읽기─────────────┘
       └─▶ 백엔드(POST /health/sync) ─▶ health_logs 적재 ─▶ GET /report (회복점수+교차검증+컨디션)

 [백업]   삼성헬스 → 개인 데이터 내보내기(CSV) ─▶ {걸음, 수면시간} ─▶ (같은 회복점수)
          ※ 폰·개발빌드 불필요 — 발표용 실데이터 경로
```

점수 로직은 **순수 함수**(DB·네트워크 없음)라 더미로 이미 테스트됨(`pytest ai/evaluation/tests/`
72개 통과). 실연동은 "같은 입력에 실데이터를 꽂는" 일.

## 6. 지금 어디까지 / 남은 일

**된 것:** 점수 엔진·어댑터·교차검증·**컨디션 추정**(`condition_signal`)·테스트·발표용 백업 파서
+ **백엔드 배선**(`get_report`가 `health_logs` 읽어 점수 반영 + `recovery_signal.condition` 노출,
`POST /health/sync` 입구) = 완료(fake-DB 테스트 검증).
**남은 것:** `health_logs` 에 **실데이터를 넣는 입구** — RN 동기화(C) 또는 export 결과 적재(A, 파일 대기).
그게 채워지면 `GET /report` 응답에 실데이터 회복점수가 그대로 나옴. (배선 자체는 양쪽 공통 = keystone)

| 버킷 | 내용 | 담당 | 상태 |
|------|------|------|------|
| **A** | 삼성헬스 export 파서 (폰 없이 발표 실데이터) | **정환주 단독** | ✅ 완료 · 실 export 파일 1건이면 컬럼 확정 |
| **B** | 백엔드 배선 (`POST /health/sync` + `get_report`가 `health_logs` 읽어 점수 반영) | **정환주** | ✅ 배선 완료 · fake-DB 테스트로 "걸음→blend 점수" 검증³ |
| **C** | RN 앱에서 삼성헬스 읽기 + 개발빌드 | 민경이 협의² | ⬜ |

¹ 2026-06-09 역할 재분담으로 백엔드 기능개발도 환주 영역(모세종 합의 대기 없이). 단 `backend/`
  푸시 전 `ruff·black·pytest`, main/dev 직접 push·커밋·PR은 규칙대로(시킬 때만).
² 삼성헬스는 Expo Go(공용 앱)로 못 읽음 → 개발빌드 필요. 공용 앱에 직접 넣으면 팀 전원
  Expo Go 깨지므로 **격리 브랜치 + 민경이 협의 + 별도 PR.**
³ **fake-DB 단위테스트로 검증(라이브 요청 아님).** `backend/tests/test_report_service.py` 의
  `test_get_report_health_logs_reach_recovery_score` — 걸음 9000이 들어오면 회복점수 산식이
  base→`blend` 로 전환되는 것까지 확인. (로컬은 starlette 버전 충돌로 앱 전체 import만 막힘 —
  CI 정상 예상. `backend/` 푸시 전 `ruff·black·pytest` 통과.)

**순서:** A(거의 완료) → B(환주 직접) → C(민경이). **A만으로 발표 실데이터 시연 가능.**

## 7. 용어 (짧게)

- **Health Connect** — 안드로이드 표준 건강데이터 허브. 삼성헬스와 **별개** → 삼성헬스 설정에서
  동기화 ON 해야 데이터가 넘어옴.
- **개발빌드** — Expo Go로 못 쓰는 네이티브 모듈을 넣은 전용 앱. Health Connect 읽으려면 필수.
- **교차검증(cross_check)** — 객관 수면 vs 주관 감정 어긋남 탐지(점수 안 깎고 플래그만).
- **재정규화(옵션 A)** — 빠진 데이터를 분모서 빼서 점수 안 깎이게 하는 방식.
- **export 백업 경로** — 폰 연동 전, 삼성헬스 데이터 내보내기 파일로 실데이터 시연하는 길.
