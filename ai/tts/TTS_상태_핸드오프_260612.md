# TTS "안 나옴" 문제 — 진단·해결 정리 (2026-06-12, 정환주)

> 팀 진도 막던 **TTS가 안 나오던 문제 해결 완료**. 무엇이 문제였고 무엇을 고쳤는지,
> 팀원별로 뭘 알면 되는지 정리합니다. (기술 몰라도 §1, §4만 보면 됩니다.)

---

## 1. 한 줄 결론

- **TTS 안 나오던 원인은 단계별로 여러 개였고 다 잡았습니다. 마지막 핵심은 "긴 추모 메시지(180자↑)는 합성이 60초를 넘겨 백엔드가 끊던 것"** → **비동기 잡 방식으로 해결**(2026-06-12 저녁 추가).
- 그 김에 터널도 **ngrok → cloudflared** 로 교체했습니다(소람님 LP와 같은 방식).
- ⚠️ **(중요·바뀜) 이제 백엔드 코드도 고쳤습니다 → 윤한님 재배포 필요.** 예전 버전 이 문서엔 "백엔드 수정 불필요"라고 적혀 있었지만 **그건 옛말**입니다. 자세히 §4·§7.

> ### 🔥 2026-06-12 저녁 최신 업데이트 (긴 메시지 → 비동기 전환)
> - **실측**: 합성 시간이 글자수에 비례(~0.33초/자). 짧은 문구(17자)=6초, **실제 추모 길이(212자)=70초**.
> - 백엔드는 한 번 호출에 **60초**까지만 기다림 → 긴 메시지는 합성 도중 끊김 = 로그의 `context canceled` → 구글 목소리로 폴백.
> - **해결**: LivePortrait와 똑같이 **"요청 제출 → 즉시 번호표(job_id) 받고 → 다 됐나 물어보기(폴링) → 결과 받기"** 방식으로 전환. 각 호출이 2초라 길이·터널과 무관하게 안전.
> - **반쪽 남음**: GPU 서버(정환주)는 완료·검증. **백엔드(윤한)는 재배포해야 적용됨** — 그 전엔 긴 메시지 여전히 끊김.

## 2. 무엇이 문제였나 (그동안 헷갈렸던 증상들)

여러 증상이 따로따로 떠서 "환주 문제다 / 터널 문제다" 혼선이 있었는데, 실제로는 단계별로 다른 원인이었습니다.

| 보였던 증상 | 진짜 원인 | 비고 |
|---|---|---|
| `status=None` → 구글 폴백 | 합성이 멈춰서 백엔드가 타임아웃 | 터널은 멀쩡했음 |
| `status=404` | 터널을 8003 직결로 바꾼 뒤 백엔드의 `/tts` 경로가 서버에 없었음 | 서버가 `/tts` 도 받게 고침 |
| `504` (Expo 앱) | 합성이 너무 느려(아래) 백엔드 앞 nginx 타임아웃 초과 | |
| "10초 0bytes / 추론 막힘" | **GPU 합성이 간헐적으로 무한 멈춤** ← 1차 핵심 | 토큰 상한으로 차단 |
| 목소리가 다 똑같이 나옴 | 백엔드가 보내는 키(`voice`)와 서버가 받는 키(`tone`)가 안 맞았음 | 서버가 둘 다 받게 고침 |
| **긴 메시지만 503/폴백** | **합성 70초 > 백엔드 60초 타임아웃** → `context canceled` | ← 2차 핵심, 비동기로 해결(§3-G) |

### 핵심 원인 (멈춤)
음성 생성 AI(Qwen3)가 **특정 문장에서 "끝"을 못 내고 최대 8192토큰까지 폭주** → 한 번 합성에 수백 초가 걸려 "멈춘 것처럼" 보였습니다.
- 정상은 1초에 끝날 합성이 → 100초+ 멈춤
- 멈춘 요청 하나가 GPU를 붙잡으면 **그 뒤 모든 요청이 같이 멈춤** → 앱에서 "TTS 안 나옴"
- 문장마다 달라서 **간헐적**으로 보였던 것 (그래서 원인 잡기 어려웠음)

## 3. 무엇을 고쳤나

**(A) 멈춤 차단** — 합성 토큰에 상한을 둬서 폭주를 막음 (`ai/tts/qwen3_synthesize.py`)
**(B) 후처리 멈춤 차단** — 속도조절(ffmpeg) 단계에도 타임아웃 추가
**(C) 전체 정지 차단** — 서버가 바쁘면 즉시 "잠시 후 재시도(503)" 응답 → 백엔드가 바로 구글 폴백 (`ai/tts/server.py`)
**(D) 경로 호환** — 서버가 `/` 와 `/tts` 양쪽, `tone`·`voice` 양쪽 키 모두 받게 함 → 백엔드가 뭘 보내든 안 깨짐
**(E) 첫 호출 느림 제거** — 서버 켤 때 모델 미리 로드 (첫 합성 20초 → 정상화)
**(F) 터널 교체** — ngrok → cloudflared (제한 없음)
**(G) ★긴 메시지 = 비동기 잡 전환** (2026-06-12 저녁) — 긴 메시지 합성이 60초를 넘겨 끊기던 문제. 서버에 "제출(`POST /synthesize/async`)→상태조회(`GET /synthesize/status/{id}`)→결과(`GET /synthesize/result/{id}`)" 3단 엔드포인트 추가(`ai/tts/server.py`). 백엔드도 단일 호출 대신 제출+폴링으로 변경(`backend/app/services/tts.py` — **윤한님 재배포 필요**). 기존 `/synthesize`는 하위호환 유지.

### 검증 결과 (실측)
- 예전에 100초 멈추던 패턴 → 지금 다 **5~10초 정상**
- 동시 요청 → 멈춤 없이 처리(1건 합성, 나머지는 즉시 폴백)
- 터널 통해 합성 왕복 **3.5초, 200 OK**
- **(G 검증)** 212자 메시지: 동기 단일호출 **69.6초** → 비동기 **개별 호출 전부 2초대**(제출·폴링·결과). 동시 3건 직렬 21초(폭증 없음). 외부 터널 통해 제출→폴링→결과 200 확인. reviewer 교차검증서 잡은 버그(백그라운드 태스크 유실) 수정 완료.

## 6. 남은 한계 (정직하게)

- **cloudflared 무료 터널은 재시작마다 URL이 바뀜** → 매번 `.env` 갱신 필요(고정 원하면 도메인 필요). 또 무료 터널은 "uptime 보장 없음"이라 끊길 수 있고, 자동시작이 부팅 때만 띄워 watchdog이 없음(끊기면 수동 재기동까지 死).
- **합성 토큰 상한 = 오디오 약 255초(~1500자)** — 추모 메시지(600자 안팎=오디오 ~100초)는 안 잘림. (2026-06-12: 옛 상한 1024=85초·~490자가 우리 메시지 끝문장을 잘라서 **3072로 상향**. 634자=93.5초 끝까지 합성 확인. 폭주(8192)는 여전히 차단.) ⚠️ 단 600~800자면 **합성에 210~285초** 걸림 → 백엔드 폴링 360초로 맞춤.
- **비동기 잡 미해결 잔여(non-blocking)**: 잘못된 입력이 비동기 경로선 400 대신 500으로 나감 / 동시 처리 상한 8건 초과 시 503. graceful degrade라 프로토타입엔 수용.
- **프론트↔백엔드 구간은 별개**: 비동기 전환은 백엔드↔GPU 구간(`context canceled`)만 해결. 프론트가 `POST /tts` 를 동기로 기다리는 구조면 긴 메시지서 프론트 쪽 타임아웃은 별도 검토 필요(LP처럼 프론트도 폴링하면 완전 해결).
- GPU 서버(`server.py`)·백엔드(`tts.py`) 코드 변경은 아직 **깃 미푸시**. **백엔드는 윤한님 재배포 전까지 라이브에 미적용**. 필요 시 PR.
